# 实验 8：Aging 防饥饿机制

## 1. 实验目的

实验 7 的严格优先级仲裁能够让高优先级队列优先使用共享资源，但当 P3 队列持续请求时，P0 队列可能永远得不到授权。本实验在保留“高优先级优先、同优先级轮询”的基础上，引入等待老化（Aging），把无限饥饿变成有界等待。

## 2. 实现方法

每个队列增加一个 7 位饱和等待计数器。队列持续有效但未获权时计数，撤销请求或成功获权时清零；Aging 关闭时计数器保持为零，避免影响原模式的综合结果。

```text
等待 0～15 周期   -> boost +0
等待 16～31 周期  -> boost +1
等待 32～63 周期  -> boost +2
等待 64 周期以上  -> boost +3
有效优先级 = min(基础优先级 + boost, P3)
```

仲裁器先找出最高有效优先级，再在相同有效优先级请求间按原轮询指针选择，因此既保留优先级语义，也避免同级队列不公平。`VX_cp_core` 将开关传入 KMU、Launch、DMA、DCR 和 Event 使用的仲裁实例，默认仍关闭，便于和 Baseline/Strict Priority 做受控对照。

## 3. 验证场景

- Test A：4 个同优先级队列持续请求，检查同级轮询公平性。
- Test B：Q0=P0、Q1=P3，二者持续请求 128 周期，检查低优先级能否获权。
- Test C：混合 P0/P1/P3 队列，检查有效优先级和同级轮询组合行为。
- Test S：Q0=P0、Q1=P3，持续竞争 512 周期，验证长期无饥饿和最大等待上界。
- 边界检查：直接核对等待计数 0、16、32、64 对应的 boost 为 0、1、2、3。
- CP 集成回归：启用 Priority+Aging 后运行 `cp_engine` 和 `cp_core` B1/100 条命令场景。

## 4. 功能结果

| 模式 | 场景 | P0 授权数 | P3 授权数 | P0 最大等待 | 是否饥饿 |
|---|---|---:|---:|---:|---|
| Strict Priority | Test B，128 周期 | 0 | 128 | 持续增长 | 是 |
| Priority+Aging | Test B，128 周期 | 1 | 127 | 64 | 否 |
| Priority+Aging | Test S，512 周期 | 7 | 505 | 64 | 否 |

低优先级队列第一次在第 64 周期获权，符合 P0 经过三级提升后达到 P3 的设计。实测最大等待为 64 周期，小于实验约束 `MAX_WAIT=128`。Test A 中四个队列各获权 100 次，公平误差为 0%。完整统计见 `results/exp08/aging_metrics.csv`，波形见 `results/exp08/aging_arbiter.vcd`。

CP 集成场景处理 100 条命令，最终 `final_seqnum=100`，`dropped_count=0`，`duplicate_count=0`，说明新增仲裁状态没有破坏命令顺序和完整性。

## 5. PPA 代理结果

| 4 路仲裁器 | FPGA LCs | FDRE | ASIC 面积（um²） | 最大路径（ns） | 400 MHz Setup Slack（ns） |
|---|---:|---:|---:|---:|---:|
| Strict Priority | 75 | 2 | 86.716 | 0.813 | 1.602 |
| Priority+Aging | 191 | 30 | 347.928 | 1.017 | 1.387 |

Aging 增加 28 个触发器，正好对应 4 个队列各 7 位等待计数。比较器、饱和加法和计数器更新逻辑也增加组合面积，使 FPGA LCs 和 ASIC 面积明显上升；但 400 MHz 约束下 setup slack 仍为正。该数据是单个 4 路仲裁器的开源工具代理综合结果，不等价于完整 CP 的最终布局布线结果。

## 6. 结论与后续方向

实验 8 消除了严格优先级的无限饥饿，并给出了 64 周期的实测服务上界。代价主要是按“队列数 × 计数器位宽”增长的寄存器和比较逻辑。后续可研究共享一组年龄状态、缩短计数位宽、参数化阈值，以及在真实多队列工作负载中同时测量吞吐、尾延迟和公平性，再决定是否默认启用。
